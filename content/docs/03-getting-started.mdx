# Your first verified app

Instead of pasting a finished template, let us build a small **local-first note outbox** step by step so you can see how Lakeport's pieces connect and how a Lean proof actually catches a bug in client logic.

## How a Lakeport app fits together

Every Lakeport screen follows a four-part loop:

1. **`State` (`structure`):** Plain immutable data held on the client (for example, offline notes waiting to sync and notes confirmed by the server).
2. **`Action` (`inductive`):** Every user click, text edit, or network callback that can happen.
3. **`step : State → Action → State`:** Pure client business logic updating state (and optionally returning `EffectReq` commands like `httpPost` or `kvSet`).
4. **`view : State → StyledView` (`.lp`):** JSX-style markup rendering `State` and mapping buttons or inputs back to `Action` values.

When you add a `*Laws.lean` file, Lean checks properties of `step` across **every** possible `State` and `Action` at compile time, then erases the proof file to `0` bytes before compiling WebAssembly.

## Step 1: Create the project manifest

Create a new directory `note-outbox/` with `lakefile.toml`:

```toml title="lakefile.toml"
name = "note-outbox"
version = "0.1.0"
defaultTargets = ["NoteOutbox"]

[[lean_lib]]
name = "NoteOutbox"
srcDir = "src"
roots = ["App", "OutboxLaws"]

[lakeport]
bundleId = "dev.example.outbox"
applicationId = "dev.example.outbox"
entry = "App"
app = "App.app"
css = "src/app.css"
outDir = "dist"

[lakeport.web]
title = "Local-First Note Outbox"
mode = "ssg"
ssgRoutes = ["/"]
```

Notice `roots = ["App", "OutboxLaws"]`: `App` is your runtime entry point, while `OutboxLaws` is a leaf proof module that `lakeport check` verifies on every build and strips from C/Wasm codegen.

## Step 2: Write a first draft reducer with a subtle retry bug

In a local-first app, users write notes offline or on spotty connections. Suppose we track three counts in `src/Outbox.lean`: `queued` notes on the device, `inFlight` (whether a note is currently being posted), and `synced` notes confirmed by the server.

Here is a realistic first draft (similar to what a coding agent often writes on its first try) where a network timeout puts the in-flight note back into `queued` so the user can retry:

```lean title="src/Outbox.lean (first draft with a retry bug)"
namespace Outbox

inductive Flight where
  | idle
  | sending
  deriving DecidableEq, Repr, Inhabited

structure Model where
  queued : Nat := 0
  flight : Flight := .idle
  synced : Nat := 0
  deriving DecidableEq, Repr, Inhabited

def Model.totalNotes (m : Model) : Nat :=
  m.queued + (if m.flight == .sending then 1 else 0) + m.synced

inductive Action where
  | addNote
  | beginSync
  | serverAck
  | timeoutDrop
  deriving DecidableEq, Repr

def step (m : Model) : Action → Model
  | .addNote =>
    { m with queued := m.queued + 1 }
  | .beginSync =>
    if m.flight == .idle && m.queued > 0 then
      { m with queued := m.queued - 1, flight := .sending }
    else m
  | .serverAck =>
    /- Bug: late HTTP 200 arrives after timeoutDrop already re-queued the note! -/
    { m with flight := .idle, synced := m.synced + 1 }
  | .timeoutDrop =>
    if m.flight == .sending then
      { m with queued := m.queued + 1, flight := .idle }
    else m

end Outbox
```

Can you spot the bug? Happy-path tests (`addNote -> beginSync -> serverAck`) pass. Yet if a slow mobile connection triggers `timeoutDrop` (moving the note back to `queued`) and the original HTTP request still reaches the server and delivers a late `serverAck`, `synced` increments anyway and duplicates the user's note!

## Step 3: State the conservation rule in OutboxLaws.lean

Ask your coding agent (or write `src/OutboxLaws.lean` directly) to enforce a plain-English rule: **sync events (`beginSync`, `serverAck`, `timeoutDrop`) must never invent or lose notes; `totalNotes` may only change on `addNote`.**

```lean title="src/OutboxLaws.lean"
import Outbox

namespace Outbox.Laws
open Outbox

theorem sync_actions_conserve_notes (m : Model) (a : Action)
    (hSync : a ≠ .addNote) :
    (step m a).totalNotes = m.totalNotes := by
  cases a with
  | addNote => contradiction
  | beginSync =>
    dsimp [step, Model.totalNotes]
    split <;> omega
  | serverAck =>
    dsimp [step, Model.totalNotes]
    cases m.flight <;> omega
  | timeoutDrop =>
    dsimp [step, Model.totalNotes]
    split <;> omega

end Outbox.Laws
```

Run `lakeport check`:

```sh title="Compiler catches the late-ack duplication bug"
$ lakeport check
src/OutboxLaws.lean:16:22: error[lean]: omega could not prove the goal:
  m : Model
  hFlight : m.flight = Flight.idle
  ⊢ m.queued + 0 + (m.synced + 1) = m.queued + 0 + m.synced
```

Look at that goal: Lean pinpointed the exact state (`m.flight = Flight.idle`) where `serverAck` added `1` to `m.synced` without a matching in-flight note!

## Step 4: Fix the state machine and re-run lakeport check

Instead of pretending a timed-out request never left the device, keep timed-out notes in `.awaitingConfirm` (with an idempotency key in a full app) and only accept `serverAck` when a note is actually `.sending` or `.awaitingConfirm`:

```lean title="src/Outbox.lean (verified state machine)"
namespace Outbox

inductive Flight where
  | idle
  | sending
  | awaitingConfirm
  deriving DecidableEq, Repr, Inhabited

def Flight.count : Flight → Nat
  | .idle => 0
  | .sending => 1
  | .awaitingConfirm => 1

structure Model where
  queued : Nat := 0
  flight : Flight := .idle
  synced : Nat := 0
  deriving DecidableEq, Repr, Inhabited

def Model.totalNotes (m : Model) : Nat :=
  m.queued + m.flight.count + m.synced

inductive Action where
  | addNote
  | beginSync
  | serverAck
  | timeoutDrop
  deriving DecidableEq, Repr

def step (m : Model) : Action → Model
  | .addNote =>
    { m with queued := m.queued + 1 }
  | .beginSync =>
    if m.flight == .idle && m.queued > 0 then
      { m with queued := m.queued - 1, flight := .sending }
    else m
  | .serverAck =>
    match m.flight with
    | .sending | .awaitingConfirm =>
      { m with flight := .idle, synced := m.synced + 1 }
    | .idle => m
  | .timeoutDrop =>
    match m.flight with
    | .sending => { m with flight := .awaitingConfirm }
    | _ => m

end Outbox
```

Update the `beginSync` / `serverAck` / `timeoutDrop` branches in `OutboxLaws.lean` with `cases h : m.flight <;> simp_all [Flight.count] <;> omega` and run `lakeport check` again:

```sh title="Zero-byte proof verification passes"
$ lakeport check
  check Outbox
  check OutboxLaws [proof-only, 0 B C]
ok (0 sorryAx, 0 unused declarations)
```

## Step 5: Render the UI in src/App.lp and src/app.css

Now connect `Outbox.Model` and `Outbox.step` to JSX markup in `src/App.lp` and styles in `src/app.css`:

```css title="src/app.css"
.shell { max-width: 560px; margin: 48px auto; padding: 24px; display: flex; flex-direction: column; gap: 16px; }
.title { font-size: 24px; font-weight: 600; }
.stats { display: flex; gap: 16px; font-family: monospace; }
.controls { display: flex; flex-wrap: wrap; gap: 8px; }
.btn { padding: 8px 16px; border-radius: 6px; border: 1px solid #BDBEBC; background: #FFFFFF; cursor: pointer; }
```

```lp title="src/App.lp"
import Outbox

namespace App
open LakeportStyle Outbox

def encodeAction : Action → Nat
  | .addNote => 1
  | .beginSync => 2
  | .serverAck => 3
  | .timeoutDrop => 4

def decodeAction : Nat → Option Action
  | 1 => some .addNote
  | 2 => some .beginSync
  | 3 => some .serverAck
  | 4 => some .timeoutDrop
  | _ => none

def view (m : Model) : StyledView Action Nat :=
  <main class="shell">
    <h1 class="title">Local-First Note Outbox</h1>
    <div class="stats">
      <span>{"Queued: " ++ toString m.queued}</span>
      <span>{"In flight: " ++ toString m.flight.count}</span>
      <span>{"Synced: " ++ toString m.synced}</span>
    </div>
    <div class="controls">
      <button class="btn" onClick={Action.addNote}>Write offline note</button>
      <button class="btn" onClick={Action.beginSync}>Send next note</button>
      <button class="btn" onClick={Action.timeoutDrop}>Simulate Wi-Fi drop</button>
      <button class="btn" onClick={Action.serverAck}>Deliver server 200 OK</button>
    </div>
  </main>

def app : StyledApp Model Unit Action Nat where
  initial := fun _ => {}
  view := view
  encodeEvent := fun a => .nat (encodeAction a)
  decodeEvent := fun | .nat n => decodeAction n | _ => none
  encodeField := .nat
  decodeField := fun | .nat n => some n | _ => none
  press := fun m a => (step m a, [])
  edit := fun m _ _ => some (m, [])
  message := fun m _ => (m, [])
  decodeNamed := fun _ _ => .error (.codec .badTag)
  commandImage := fun _ => none
  appCommit := fun m => m.totalNotes
  descriptor := "note-outbox/1"
  profile := ⟨⟨32, 65536⟩, ⟨32, 65536⟩⟩

end App
```

Run `lakeport dev` to test in your browser, or `lakeport build web --release` to emit pre-rendered HTML and `app_lp2.wasm` in `dist/web/`.

<Callout kind="important" title="A candid note on <button>, clickable cards, and gestures">
As soon as you build richer UI beyond text buttons (such as a clickable card with an icon and badge), you will notice that Lakeport currently only permits `onClick` on `<button>`, and `<button>` only accepts a `String` label. That is **not** a philosophical feature; it is a real constraint inherited from freezing Lakeport's 4-constructor `ViewApi` kernel early (and it is the exact reason React Native provides `Pressable` / `onPress` on arbitrary containers). In [Views, SDKs, and .lp TSX](/docs/views-and-tsx), we show the `.hit-overlay` CSS workaround used across `lakeport.dev` today and state plainly which gestures (such as touch swiping) are not yet wired into Lean.
</Callout>
