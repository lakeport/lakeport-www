# Installation and project layout

Lakeport compiles `.lp` views, `.css` stylesheets, and Lean 4 modules into static HTML and WebAssembly through one CLI binary: `lakeport`.

## 1. Verify your toolchain with lakeport doctor

After placing `lakeport` on your `PATH`, run `lakeport doctor` to inspect the local tools used for type-checking and WebAssembly builds:

```sh title="Check local build dependencies"
lakeport doctor
```

For web development and production SSG builds, `lakeport doctor` checks:

- **Lean 4.35 (`elan` / `lean` / `lake`):** Type-checks reducers, `.lp` views, and `*Laws.lean` theorems, and emits C11 sources.
- **Emscripten (`emcc`) & Binaryen (`wasm-opt`):** Links C11 runtime code with `-Oz -flto -Wl,--gc-sections` into compact `wasm32` binaries.
- **Node.js (v20+):** Executes `app_lp2.wasm` at build time to pre-render static HTML pages for every route in `ssgRoutes`.

If you only run `lakeport check` in CI or inside an agent loop, Emscripten is not invoked until `lakeport build web`.

## 2. Connect your coding agent with lakeport mcp

Most teams use Lakeport alongside Claude Code, Codex, or Cursor. Registering `lakeport mcp` gives your agent structured compiler diagnostics (exact `.lp`, `.css`, and `.lean` file paths, 1-indexed lines, error codes, and open proof goals) instead of raw terminal text:

```toml title="Example MCP configuration"
[mcp_servers.lakeport]
command = "lakeport"
args = ["mcp"]
```

Once connected, your agent can iterate on a reducer and its `*Laws.lean` proof automatically before handing the result back to you.

## 3. Standard single-app directory layout

A Lakeport web app needs only `lakefile.toml` and `src/`. You do **not** need a `shared/` workspace package unless you are publishing a reusable library across multiple Lean repositories:

```text title="Typical Lakeport web repository"
my-app/
  lakefile.toml          # App manifest, CSS entry, and ssgRoutes list
  src/
    app.css              # Global design tokens and component rules
    App.lp               # Root StyledApp mount, navigation chrome, and views
    Outbox.lean          # Pure client state and step reducer
    OutboxLaws.lean      # [proof-only, 0 B C] theorems checked on every build
    Api/
      Orders.lean        # Frontend JSON decoders for your Go/Node/Python API
```

<Callout kind="tip" title="Five SDKs are available automatically">
Lakeport's build driver automatically imports `LakeportStyle`, `LakeportRouter`, `LakeportEffects`, `LakeportJson`, and `LakeportXml` into your project build graph, so you can open `LakeportJson` or `LakeportEffects` in any `.lean` or `.lp` module without extra `lakefile.toml` boilerplate.
</Callout>
