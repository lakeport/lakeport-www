# Styling, CSS modules, and .lpcss

Stylesheets in Lakeport are ordinary `.css` files verified at compile time rather than untyped runtime strings or JavaScript CSS-in-JS objects. One `.css` pipeline produces `bundle.css` for browsers and a binary `LPCS` (`bundle.lpcss`) style sheet for native host shells.

## Compile-time class verification

When you write `class="card card-header"` in a `.lp` file, Lakeport parses `[lakeport] css = "src/app.css"` before Lean runs and checks every class token against your stylesheet and Lakeport's built-in layout utility index.

Renaming `.card-header` in `src/app.css` without updating a `.lp` reference fails `lakeport check` immediately with a source-mapped error:

```sh title="Compile-time CSS diagnostic"
src/Marketing.lp:42:10: error[css-global]: unknown CSS class "card-header":
  not defined by the global stylesheet and not a supported utility
```

## Scoped package stylesheets with import_css

Reusable packages (such as `packages/lakeport-mdx`) should never collide with an application's global class names. Any `.lp` module can bind a co-located stylesheet using `import_css`:

```lp title="packages/lakeport-mdx/src/LakeportMdx/Render.lp"
import LakeportMdx.Ast
import_css MdxCss from "./Mdx.css"

def badge (lang : String) : StyledView E F :=
  <span class={MdxCss.langBadge}>{lang}</span>
```

During lowering, Lakeport computes a 6-character SHA-256 prefix from the module identity, rewrites `.langBadge` into a scoped selector inside Cascade Layer L5 of `bundle.css`, and exposes `MdxCss.langBadge : ClassName` so typos fail compilation cleanly.

## Dynamic state with data-* attributes and CSS custom properties

Static `class="..."` strings allow the compiler to hoist `NodeStyle` records into top-level constants (`_lp_ns_k`) instead of allocating class arrays on every render frame. Express dynamic visual state with typed `data-*` attributes and `--*` CSS custom properties:

```lp title="Static class + typed data attribute"
<div class="sync-pill" data-status={state.statusSlug} --pill-progress={progressPct}>
  <span>{state.statusLabel}</span>
</div>
```

```css title="src/app.css"
.sync-pill {
  padding: 4px 12px;
  border-radius: 8px;
  background: var(--surface);
  color: var(--ink-muted);
}
.sync-pill[data-status="synced"] {
  background: var(--proved-soft);
  color: var(--proved);
}
```

## Light and dark themes via token overrides

Define semantic surface, text, border, and evidence variables (`--bg`, `--surface`, `--ink`, `--brand`, `--proved`, `--trusted`, `--unknown`, `--failed`) on your root shell class, then override **only the variables** under `@media (prefers-color-scheme: dark)` and `[data-theme="dark"]`. Every component inherits both themes automatically without duplicating layout rules.
