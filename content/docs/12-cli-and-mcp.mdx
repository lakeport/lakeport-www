# CLI and MCP workflow reference

Everything in Lakeport runs through one native binary (`lakeport`) without external Webpack, Vite, Babel, or PostCSS configuration files.

## Core CLI commands

| Command | Purpose |
| --- | --- |
| `lakeport init <dir>` | Scaffolds `lakefile.toml`, starter `src/App.lp`, `src/app.css`, and coding-agent instructions. |
| `lakeport check [dir]` | Verifies global and scoped CSS classes, lowers `.lp` files with 1:1 line maps, checks all `.lean` and `*Laws.lean` theorems (`0 sorryAx`), and runs `.ilean` reachability + zero-`Float` audits. |
| `lakeport dev [dir]` | Runs a local development server watching `.lp`, `.css`, and `.lean` files with structured reload diagnostics. |
| `lakeport build web [dir] --release` | Runs `check`, compiles reachable C11 modules to `wasm32` (`-Oz -flto --gc-sections` + `wasm-opt -Oz`), and pre-renders all `ssgRoutes` to `dist/web/`. |
| `lakeport build <target> [dir]` | Builds experimental native host targets (`linux`, `macos`, `windows`, `ios`, `android`; platform UI gates remain open). |
| `lakeport doctor` | Verifies `lean`, `lake`, `emcc`, `wasm-opt`, `node`, and optional native SDKs on the host machine. |
| `lakeport mcp` | Launches the Model Context Protocol stdio server so coding agents can invoke structured compiler checks directly. |

## Structured diagnostics over lakeport mcp

Configuring Claude Code, Codex, or Cursor to run `lakeport mcp` gives your agent machine-readable JSON diagnostics instead of raw terminal text:

```toml title="Registering lakeport mcp"
[mcp_servers.lakeport]
command = "lakeport"
args = ["mcp"]
```

Each diagnostic entry reports:

- Exact source path (`src/Widgets.lp`, `src/app.css`, or `src/OutboxLaws.lean`) mapped back from lowered `.lean` coordinates.
- 1-indexed line and column numbers.
- Category code (`css-global`, `css-module`, `tsx-tag`, `tsx-attr`, `lean`, `float-ban`, or `dead-decl`).
- Unsolved Lean proof goals when a `*Laws.lean` theorem fails after a reducer edit.

## Negative union checks in CI

To guarantee that nobody introduces a catch-all `_ =>` wildcard arm into a critical schema union, add a small negative test in CI (like `tests/check-negative-v3.py` in `lakeport-www`): copy the workspace to a temp folder, inject a dummy `| v3` constructor into your schema enum, run `lakeport check`, and assert that compilation **fails** naming the missing `v3` case.
