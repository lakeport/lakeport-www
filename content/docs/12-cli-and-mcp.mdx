# CLI and MCP workflow reference

Everything in Lakeport runs through a single native command-line binary: `lakeport`. There is no separate bundler config, Babel plugin chain, or CSS-in-JS PostCSS wrapper to maintain.

## Everyday commands

| Command | What it does |
| --- | --- |
| `lakeport check [dir]` | Lowers `.lp` TSX, validates global and scoped CSS classes, type-checks all `.lean` modules and `*Laws.lean` theorems, and maps diagnostics back to `.lp`/`.css` line numbers. |
| `lakeport build web [dir] --release` | Runs `check`, compiles reachable runtime modules to `wasm32` (`-Oz`, LTO, `--gc-sections`, `wasm-opt`), pre-renders all `ssgRoutes` to static HTML, and emits `dist/web/`. |
| `lakeport dev [dir]` | Starts a local development server with automatic rebuilds on `.lean`, `.lp`, and `.css` edits. |
| `lakeport build <target> [dir]` | Builds native target outputs (`linux`, `macos`, `windows`, `ios`, `android`). |
| `lakeport doctor` | Audits installed compilers, linkers, Binaryen, Node, and platform SDKs. |
| `lakeport mcp` | Starts the Model Context Protocol server over stdio so coding agents can invoke structured checks and inspect diagnostics. |

## Connecting coding agents with lakeport mcp

Instead of letting an AI coding agent scrape raw terminal output with fragile regexes, configure your editor or agent harness to launch `lakeport mcp`:

```toml title="MCP server configuration"
[mcp_servers.lakeport]
command = "lakeport"
args = ["mcp"]
```

Through MCP, the agent receives structured JSON diagnostics with exact `.lp`, `.css`, and `.lean` file paths, 1-indexed line and column numbers, error codes (`css-global`, `tsx-attr`, `lean`), and concrete fix hints (such as reminding the agent to add `key={...}` on mapped list children or naming which stylesheet binding missed a class).

## Running negative contract checks in CI

Positive builds verify that your current code compiles. For shared edge contracts (`shared/`), we also recommend a 30-line negative check script in CI (`tests/check-negative-v3.py`) that copies `shared/` into a temporary directory, appends `| v3` to `Version`, and asserts that `lakeport check` **fails** with an unhandled union case error.

Why test that a broken program fails to compile? Because it prevents anyone from accidentally adding a `| _ =>` wildcard catch-all to `clientHandler` six months later. If someone sneaks a wildcard arm in, adding `| v3` would unexpectedly *succeed*, failing the negative CI check and catching the regression right in code review.
