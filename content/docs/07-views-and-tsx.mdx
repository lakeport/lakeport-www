# SDK map, views, and .lp TSX

Before diving into `.lp` component syntax, here is a complete map of the **modules and capabilities** bundled with Lakeport so you know what exists out of the box without hunting through source directories.

## Built-in SDKs and capability plugins

Lakeport automatically wires **five pure-Lean SDKs** into every application build, plus **three optional capability plugins** for streaming transports, device hardware, and local inference:

| Module | Import / ID | What it gives you |
| --- | --- | --- |
| `lakeport-style` | `open LakeportStyle` | `StyledView` JSX nodes, CSS class verification, `MemoCell` / `MemoKeyedList`, and binary `LPST` style diffing. |
| `lakeport-router` | `open LakeportRouter` | `UrlCodec`, `LawfulUrlCodec` round-trip proofs, `RouterState` (stack, sheet, drawer), and `<RouterShell>`. |
| `lakeport-effects` | `open LakeportEffects` | `18` typed `EffectReq` / `EffectResp` host commands (HTTP, WS, KV, clipboard, haptics, timers, plugins) and idempotent `Outbox`. |
| `lakeport-json` | `open LakeportJson` | SWAR-accelerated RFC 8259 `Json.parse`, `Json.stringify`, `ToJson` / `FromJson`, `fieldAs`, streaming NDJSON, and round-trip laws. |
| `lakeport-xml` | `open LakeportXml` | Pure-Lean XML lexer, tree parser, serializer, and escapes for RSS, SVG, and enterprise XML payloads. |
| `@lakeport/transport` | Plugin ID `"transport"` | Server-Sent Events (SSE), chunked binary frame streams, and multipart uploads beyond the core `64 KB` effect ceiling. |
| `@lakeport/media-device` | Plugin ID `"media-device"` | Camera/microphone capture, geolocation, Bluetooth LE scans, network reachability, and native haptics. |
| `@lakeport/on-device-ai` | Plugin ID `"on-device-ai"` | Structured invocation and token streaming for local/on-device model runtimes. |

## Supported .lp JSX elements

Lakeport `.lp` files let you write JSX markup directly inside Lean 4 modules. Prior to elaboration, `LpTsx.lean` lowers JSX tags to `LakeportStyle.StyledView` values while preserving 1:1 line numbers so compiler diagnostics point straight at your `.lp` file:

- **Layout and landmarks (`10`):** `div`, `span`, `header`, `section`, `main`, `aside`, `footer`, `nav`, `p`, and headings `h1`, `h2`, `h3` (`12` text/container tags total)
- **Interactive controls (`3`):** `button`, `input`, `textarea`
- **Media and vector graphics:** `img` (requiring `src` and `alt`) and `svg` (`path`, `circle`, `rect`, `line`, `polyline`, `polygon`, `ellipse`, `g`, `defs`, `linearGradient`, `clipPath`, lowered to `data-lp-svg*` attributes for Web DOM and native vector renderers)

## Candid guide: buttons, .hit-overlay, and gestures (like swiping)

If you try writing `<div onClick={ev}>` or nesting an `<svg>` icon and two `<span>`s inside `<button>`, `lakeport check` rejects it:

1. `onClick={ev}` is only accepted on `<button>`.
2. `<button>` only accepts a `String` child (no nested elements).

**Why is it like this?** Honestly, this is an architectural trade-off (and a rough edge) from freezing Lakeport's verified kernel (`ViewApi` in `lakeport-core`) early around four minimal constructors: `.text`, `.button (label : String) (action : E)`, `.input`, and `.group`. Keeping `ViewApi` tiny made it tractable to prove reconciliation and capacity rollback theorems, yet in real UI work people constantly need clickable cards, icon buttons, and row items. It is the exact reason React Native introduced `Pressable` and `onPress` on non-button containers rather than forcing every tap target through a text-only button.

**How to build clickable cards and icon buttons today (`.hit-overlay`):** Layer a full-bleed `<button class="hit-overlay" onClick={ev}>Accessible label</button>` inside a `position: relative` container and set `pointer-events: none` on visual sibling elements:

```lp title="Clickable card workaround used across lakeport.dev"
def chapterCard (title summary : String) (ev : UiEvent) : V :=
  <div class="chapter-card">
    <button class="hit-overlay" onClick={ev}>{title}</button>
    <span class="chapter-title">{title}</span>
    <p class="chapter-summary">{summary}</p>
  </div>
```

```css title="src/app.css"
.chapter-card { position: relative; }
.hit-overlay { position: absolute; inset: 0; opacity: 0; cursor: pointer; }
.chapter-title, .chapter-summary { pointer-events: none; }
```

This keeps real `<button>` keyboard focus, Enter/Space activation, and screen-reader labels intact, though it is undeniably boilerplate compared to a native `Pressable` container.

**What about swiping and touch gestures?** Today, Lakeport's core event channel models discrete **presses** (`onClick`), **controlled text edits** (`field={id}`), **keyboard shortcuts** (`data-hotkey`, `data-submit`), and **pointer ghost-drag reorder/drop** (`data-lp-draggable` / `data-lp-drop-zone` mapped onto synthetic buttons). Continuous touch gestures (**horizontal swipe-to-dismiss, pan/pinch, scroll position callbacks, and focus/blur events**) do **not** cross into Lean state yet. On the web, CSS scroll-snap carousels work purely in the browser, while gesture-driven state machines require extending `ViewApi` or bridging a host gesture plugin.

## Controlled inputs and keyed lists

`<input>` and `<textarea>` bind to your `StyledApp`'s field identifier type `F` via `field={...}`:

```lp title="Controlled search box"
<input
  class="search-input"
  field={1}
  value={state.query}
  label="Filter chapters"
  placeholder="Filter chapters..."
/>
```

When rendering dynamic `List` or `Array` collections that can reorder or delete mid-list, supply a stable `Nat` key with `key={item.id}` (or use `MemoKeyedList` for large lists).

## Zero-stale-dependency caching with MemoCell

Unlike React's `useMemo`, where forgetting an item in `[depA, depB]` causes stale UI bugs, `LakeportStyle.MemoCell α β f` stores `(input : α)`, `(output : β)`, and an erased proof `coherent : output = f input`.

On a cache hit (`c.input == x`), `c.refresh x` returns the cached `output` with zero allocations; on a change, it recomputes `f x`. The kernel theorem `MemoCell.refresh_get` guarantees `(c.refresh x).get = f x`, and `coherent` erases to `0` bytes at runtime.
