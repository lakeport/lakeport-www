# Effects, JSON, and offline sync

Because your reducer is pure, side effects cross an explicit data boundary: `press`, `edit`, and `message` return `(State × List Term)` built from `LakeportEffects.EffectReq`. The host runtime executes each request asynchronously and feeds a typed `EffectResp` back into `app.message`.

## All 18 built-in EffectReq operations

`LakeportEffects` provides `18` typed host commands grouped into five families:

- **HTTP & Streaming (`5`):** `.httpGet`, `.httpPost`, `.httpRequest` (custom method + request headers), `.httpStream` (chunked / SSE delivery), `.httpCancel`
- **WebSockets (`4`):** `.wsConnect`, `.wsSend`, `.wsSendBytes`, `.wsClose`
- **Key-Value Storage (`3`):** `.kvGet`, `.kvSet`, `.kvDelete` (`localStorage` on web; native preferences on desktop and mobile shells)
- **UX & Timers (`3`):** `.clipboardWrite`, `.haptic` (`light`, `medium`, `heavy`, `success`, `warning`, `error`), `.sleepMs`
- **Capability Plugins (`3`):** `.pluginInvoke`, `.pluginSubscribe`, `.pluginUnsubscribe` (used by `@lakeport/transport`, `@lakeport/media-device`, and `@lakeport/on-device-ai`)

Every command carries a caller-chosen `reqId : Nat` so your reducer can correlate responses, timeouts, and cancellations deterministically.

## Parsing JSON and XML without Float drift

`LakeportJson` and `LakeportXml` are pure Lean 4.35 SDKs with zero external C parser dependencies:

- **`LakeportJson`:** Uses exact decimal `JsonNumber` (`mantissa : Int`, `exponent : Nat`) rather than IEEE-754 `Float`, so parsing stays bit-identical across `wasm32` and 64-bit native targets. Includes `Json.parse`, `Json.stringify`, `ToJson` / `FromJson`, `j.fieldAs`, `j.fieldOpt`, streaming `JsonChunkParser`, and parallel `JsonTape` indexing.
- **`LakeportXml`:** Provides total fuel-bounded XML lexing, element tree parsing, and attribute/entity escaping.

## Local-first Outbox and mid-flight disconnects

Local-first apps persist user edits locally first (via `.kvSet`) and sync them in the background. Network drops expose a critical distinction that naive retry loops get wrong:

1. **Definite server rejection (HTTP `4xx` / `422`):** The server never applied the mutation; mark the item rejected or ask the user to edit it.
2. **Uncertain delivery (`.unknownOutcome`: socket drop, airplane mode, `502`/`504` timeout):** Your request bytes *may or may not* have reached the backend database before the connection died.

`LakeportEffects.Outbox` models each queued entry with a stable client-generated idempotency key (`clientMutationId`). When an HTTP call fails with a network drop, transition that entry to `.unknownOutcome` and replay the **same** `clientMutationId` on reconnect rather than minting a brand-new mutation ID.

## Service Worker caching for offline Lakeport web apps

To make a Lakeport web app boot offline, register a standard browser Service Worker alongside your `dist/web/` output:

- **Precache core runtime assets:** Cache `/wasm/app_lp2.wasm`, `/wasm/app_lp2.js`, `/runtime/boot.mjs`, `/bundle.css`, and your `.woff2` fonts inside one versioned cache key (`lakeport-shell-vN`) so the JS shim and `.wasm` binary always upgrade together.
- **Route HTML strategy:** Use `network-first` (falling back to cached SSG HTML when offline) or `stale-while-revalidate` for navigation requests so online users pick up new deployments promptly while offline users still boot immediately.
- **Keep backend schema unions aligned with cache lifetime:** Remember that a user booting from a Service Worker cache runs yesterday's `.wasm` binary against today's server until the new Service Worker activates; see [Frontend JSON schema unions](/docs/versioned-contracts).

<Callout kind="warning" title="64 KB ceiling on core EffectResp payloads">
Because core `EffectResp` messages cross the fixed `64 KiB` `g_input_buf` `LP2` buffer using `LPDT` framing, `boot.mjs` currently caps individual `EffectResp` bodies at `64,000` bytes (`effectLimits = 65536`). Keep REST responses paginated below `64 KB`, or stream larger downloads in chunks via `.httpStream` / `@lakeport/transport`.
</Callout>
