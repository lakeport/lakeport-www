# Reservoir modules and bundle size

In the JavaScript ecosystem, importing one utility from an npm package often drags along transitive polyfills and top-level module side effects that bundlers cannot safely tree-shake.

Pure Lean 4 modules have no implicit top-level side effects and expose a complete static declaration call graph in `.ilean` artifacts. You can pull rich packages from [Reservoir](https://reservoir.lean-lang.org) (Lean's package registry) or local workspace paths in `lakefile.toml`, include extensive `*Laws.lean` proof suites, and pay WebAssembly bytes **only** for runtime functions reachable from `App.app`.

```toml title="Adding packages in lakefile.toml"
[[require]]
name = "lakeport-mdx"
path = "packages/lakeport-mdx"
```

## Five stages of proof and dead-code stripping

During `lakeport build web --release`, unused code and proof machinery drop out across five stages:

1. **`Prop` erasure (`0 B`):** Every value of type `Prop` (such as `MemoCell.coherent`, `SafeSlug`, or equality witnesses) is erased inside the Lean compiler before IR emission. Proof size never increases function code size.
2. **Leaf law module omission (`[proof-only, 0 B C]`):** Modules like `WorkbenchLaws.lean` and `SiteLaws.lean` are kernel-checked during `lakeport check` and skipped completely when invoking `lean -c` for C codegen.
3. **`meta` phase separation (`0 B`):** Compile-time macros and syntax elaborators execute while producing `.olean` files and never emit runtime C symbols.
4. **Per-declaration C sections + LTO (`-ffunction-sections -fdata-sections -Oz -flto -Wl,--gc-sections`):** Unreferenced C functions and static tables are garbage-collected by `wasm-ld`.
5. **Binaryen whole-program pass (`wasm-opt -Oz`):** Compacts WebAssembly locals, folds constants, and inlines small wrappers across the linked module.

## Catching dead code early with .ilean reachability

During `lakeport check`, Lakeport runs a breadth-first search over `.ilean` reference graphs starting from `App.app` (`proofAnchoredDeclarations`). If you delete a retired `OrderSchema.v1` branch and leave behind helper functions referenced **only** by an orphaned theorem in `*Laws.lean` (and nowhere in your runtime app), `lakeport check` warns you immediately so dead helpers do not linger in your repository.
